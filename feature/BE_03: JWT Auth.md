# BE_03: JWT Auth

Необходимо добавить в API аутентификацию по JWT поверх уже существующего пакета `user` (BE_02).

## Цель

Пользователь может зарегистрироваться и войти, получив JWT-токен. Защищённые эндпоинты доступны
только при наличии валидного токена в заголовке `Authorization: Bearer <token>`.

## Создать пакет `auth`

Разделить по уровням как в `user`: Controller → Service. Плюс инфраструктура безопасности
(провайдер токена, фильтр) — в `auth` или `common` на твоё усмотрение.

## Эндпоинты

- `POST /api/auth/register` — регистрация: принимает имя, email, пароль; создаёт пользователя
  (переиспользовать логику из `UserService`), возвращает JWT-токен (или токен + данные пользователя).
- `POST /api/auth/login` — вход: принимает email и пароль; проверяет пароль через
  `PasswordEncoder.matches()`; при успехе возвращает JWT-токен, при неверных данных — 401.

## JWT

- Генерация и валидация токена (отдельный компонент, напр. `JwtTokenProvider`).
- В токене хранить как минимум идентификатор пользователя (subject) и срок жизни (expiration).
- Секрет и время жизни токена — через переменные окружения / `application.properties`
  (с дефолтами для локалки).
- Фильтр, который на каждом запросе достаёт токен из заголовка `Authorization`, валидирует его
  и кладёт пользователя в `SecurityContext`.

## Security

- Обновить `SecurityConfig` (из BE_02): заменить временный `permitAll()` на реальные правила —
  `/api/auth/**` открыт, остальное требует аутентификации.
- Встроить JWT-фильтр в цепочку до стандартного `UsernamePasswordAuthenticationFilter`.
- Сессии — stateless (`SessionCreationPolicy.STATELESS`).

## Прочее

- DTO отделить от Entity (как в BE_02): отдельные request/response для register и login.
- Обработку ошибок (неверный логин/пароль, истёкший токен) свести к понятным HTTP-кодам
  (401/403), переиспользовать `GlobalExceptionHandler` где уместно.
- Пароль в ответах и логах не светить.

## Возможные служебные детали на твоё усмотрение

- Библиотека для JWT (например, `jjwt`).
- Формат ответа login/register (только токен или токен + профиль).
- Эндпоинт `GET /api/auth/me` для получения текущего пользователя по токену.
